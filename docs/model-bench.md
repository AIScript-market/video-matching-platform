# 모델 비교 계획과 결과 (사전 등록)

> 이 문서의 "계획" 절은 **모델을 하나도 돌려 보기 전에** 커밋했다. 결과를 보고 규칙을 바꾸지 않았다는 근거다.
> 친구 컴퓨터용 키트 안내는 [`services/ml/research/bench_kit/README.md`](../services/ml/research/bench_kit/README.md).

## 왜 하는가

지금까지는 표현 하나(bge-m3, 문자 n그램)와 학습기 하나(주성분 16개 + 로지스틱)로만 쟀다.
학습기는 원래 수백 편 규모에 맞춘 설정이라, 수천 편인 영화·TV 자료에서는 정보를 버리고 있을 수 있다.
그래서 표현과 학습기를 바꿔 같은 잣대로 비교한다.

## 계획

### 과제 셋

| 과제 | 자료 | 정답 | 나누는 단위(group) | 비교 단위(eval_group) | 성격 |
|---|---|---|---|---|---|
| movies | CMU 영화 줄거리 6,930편 | 박스오피스 나머지, 같은 장르×5년 안 상위 1/3 | 장르×5년 | 장르×5년 | **주 과제** (신호가 있었던 자료) |
| tv | 위키백과 TV 에피소드 9,165화 | 다음 화 시청자 유지, 같은 시리즈 안 상위 1/3 | 시리즈 | 시리즈 | 대조 과제 (신호가 없던 자료) |
| novels | 구텐베르크 소설 466편 | 영상화 여부 | 작가 | 작가×장르 | 참고 (시험용이 작가 11명뿐) |

### 시험용 잠금

- 나누는 단위의 이름을 SHA-256으로 해시해서 `% 5 == 0`인 묶음을 시험용으로 정한다(약 20%). 결과를 보고 바꿀 수 없다.
- 개발용은 같은 해시로 묶음 단위 5겹(`fold`)으로 나눈다. 모든 모델과 친구 실험이 같은 겹을 쓴다.
- 시험용 정답은 `services/ml/research/data/bench/`(저장소·키트에서 제외)에만 둔다. 파일 SHA-256:

| 과제 | 개발용 | 시험용 | 시험용 정답 SHA-256 |
|---|---|---|---|
| movies | 5,676편 (150묶음) | 1,254편 (40묶음) | `8d599b102321a8eaef04562410f946f24a90905f0ecf5c8e458554d768a16281` |
| tv | 6,782화 (61시리즈) | 2,383화 (17시리즈) | `cb8c41a75e77e08c3ce5071c09661e1078bf413aacb5cb5c1b2bff8eaca8bcd6` |
| novels | 375편 (46작가) | 91편 (11작가) | `d78c9bf97c72efcc78ff1a44325719703f50ca24a182be86bce4c464439127e9` |

### 잣대

1. 모델 점수에서 비교 단위 고정효과와 글 길이(log 낱말 수, 소설은 log 글자 수) 몫을 회귀로 뺀다.
2. 같은 비교 단위 안의 (흥행, 아닌 것) 쌍만 세어 AUC. 구간은 비교 단위를 다시 뽑는 부트스트랩 1,000회.
3. 개발용은 5겹 교차검증 점수로, 시험용은 개발용 전부로 학습한 모델 점수로 잰다. 시험용 p값은 비교 단위 안 순열 2,000회.

채점기는 [`bench_eval.py`](../services/ml/research/bench_kit/bench_eval.py) 하나다. 우리 비교와 친구 실험이 같은 코드로 채점된다.

### 비교할 모델 (여기서 더 늘리지 않는다)

| 이름 | 표현 | 학습기 |
|---|---|---|
| `pca16-logit` | bge-m3 | **기준**: 주성분 16개 + 로지스틱 (지금까지 방식, 이야기 요소는 뺐다) |
| `logit-full` | bge-m3 | 1,024차원 그대로 로지스틱 |
| `ridge-score` | bge-m3 | 연속 흥행 점수를 맞히는 릿지 |
| `ridge-within` | bge-m3 | 묶음 안에서 중심화한 벡터·점수로 릿지 (묶음 안 비교로 학습) |
| `hgb-pca64` | bge-m3 | 그래디언트 부스팅 (주성분 64개, 묶음 안 중심화) |
| `knn50` | bge-m3 | 가장 비슷한 50편의 묶음 안 성적 평균 |
| `tfidf-ridge` | 낱말 1~2그램 TF-IDF | 릿지 (bge-m3 안 씀) |
| `blend` | 둘 다 | `ridge-within`과 `tfidf-ridge` 점수 평균 |

규제 세기는 학습 쪽 안에서만 고른다(릿지는 일반화 교차검증, 로지스틱은 묶음 3겹).

### 고르는 규칙과 시험

- 과제마다 개발용 AUC가 가장 높은 모델 하나를 고른다.
- 시험용에서는 **기준 모델과 고른 모델 두 개만**, 과제마다 **한 번** 잰다(`bench-test`는 두 번째 실행을 거부한다).
- "기준보다 낫다"는 시험용에서 차이(고른 모델 − 기준)의 95% 구간 하한이 0보다 클 때만 말한다. 아니면 "개선을 확인하지 못함"이다.
- tv는 대조 과제다. 개발용에서 신호가 보이는데 시험용에서 사라지면, 모델 고르기가 우연을 고른 것으로 본다.
- novels는 시험용이 작아 서술만 한다.
- 결과와 상관없이 파일럿 GO 기준(같은 채널 안 0.60)은 바꾸지 않는다.

### 친구 실험

- 친구는 키트의 개발용(정답 포함)과 시험용(정답 없음)을 받는다. 개발용 점수는 `bench_eval.py`로 스스로 잰다.
- 시험용 예측은 우리에게 보내 `python -m research bench-score`로 채점한다. **과제마다 키트 버전당 3번까지**, 실패한 것까지 모두 이 문서에 적는다.
  여러 번 내면 그만큼 우연히 좋은 결과가 나올 기회가 늘어서다.
- 시험용 정답은 공개 자료에서 다시 만들 수 있다. 친구에게는 원본 박스오피스·시청자 수를 찾아보지 말아 달라고 부탁한다(정직하게 하는 실험).
