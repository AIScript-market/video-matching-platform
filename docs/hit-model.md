# 흥행 판단 모델

목표: 영상 제작자에게 **"A급 PD의 감"**을 주는 것. 경험 많은 PD가 수백 편을 보고 몸으로 익힌 판단을, 우리 플랫폼에 쌓이는 대본과 성과 데이터로
기록하고 전하는 일이다. 한비자가 군주 곁에 늘 유능한 신하가 있을 수 없으니 판단의 원리를 글로 남겼듯, 모든 제작자 곁에 A급 PD가 있을 수는 없으니
그 감을 모델로 남긴다.

**LLM API를 부르지 않는다.** LLM에게 대본 점수를 매기게 하면 누구나 똑같이 만들 수 있고(무형자산이 안 된다), 실제 성과와 연결되지도 않는다.
우리 모델은 **대본을 벡터로 바꾸고, 우리 플랫폼 작품의 실제 성과(조회수·좋아요·긍정 댓글)와 연결해 학습한 통계 모델**이다.
데이터가 쌓일수록 좋아지고, 그 데이터는 우리만 갖는다.

## 구조

```
대본 본문 ─ 장면 나누기 ─ 장면 벡터 ─ 대본 벡터 ─┐
             └ 구조 특징 (장면 수, 대사 비율, 인물 수, 밤 장면, 첫 장면 비중 …) ─┤
                                                                      ├─ 우리 모델 → "상위 20% 성과일 확률" + 범위
작품 성과 (조회수·좋아요·긍정 댓글·채널 구독자) ─ 채널 크기 보정 ─ 정답 ────┘
```

| 부분 | 위치 | 내용 |
|---|---|---|
| 벡터화 | `services/ml/hitmodel/segment.py`, `embedders.py` | 장면 머리(`S#1.`, `#3`, `씬 4`, `INT.` …)로 나누고 장면마다 벡터를 만든다. 대본 벡터는 장면 벡터를 길이의 제곱근으로 가중 평균 |
| 저장 | `ScriptEmbedding` | 대본 벡터, 장면 벡터(앞 300장면), 구조 특징, 본문 해시, 임베더 이름. 본문이 바뀌면 다시 만든다 |
| 정답 | `services/ml/hitmodel/labels.py` | 아래 "정답" 참고 |
| 모델 | `services/ml/hitmodel/model.py` | 주성분 + L2 로지스틱 회귀 + 부트스트랩, 시간 순서 검증 |
| 버전 | `HitModelVersion` | 학습한 모델, 검증 지표, 정답 정의, 활성 여부 |
| 연결 | `apps/api/src/modules/hit-model` | 제작자용 판단·추천, 관리자 학습 화면. ML 서비스는 내부 주소로만 부른다 |
| 화면 | 대본 상세 "흥행 판단", `/recommendations`, `/admin/ml`, 작품 성과 입력 | |

### 임베더
- 기본은 **문자 1~3그램 해시 임베더**(`hash-ngram-v1-d512`)다. 학습도 외부 API도 필요 없고, 같은 글이면 언제나 같은 벡터가 나온다.
  한국어는 음절 하나가 의미 단위에 가까워서 소재·말투·장면 분위기 차이를 꽤 잡는다.
- 더 좋은 벡터가 필요하면 `ML_EMBEDDER=bge-m3`로 공개 다국어 임베딩 모델을 **우리 서버에서** 돌린다(`requirements-bge.txt`). 대본이 밖으로 나가지 않는다.
- 임베더가 바뀌면 벡터와 모델을 모두 다시 만든다(이름이 함께 저장된다). 나중에 우리 데이터로 임베더 자체를 미세조정할 수 있다.

### 정답
채널 크기를 걷어내야 대본의 힘을 볼 수 있다. 구독자 100만 채널의 10만 회와 1만 채널의 10만 회는 다르다.

- 도달 = log(1+조회수) − log(1+공개 시점 채널 구독자)
- 반응 = (좋아요 + 3 × 긍정 댓글) ÷ 조회수
- 점수 = z(도달) + z(반응), **상위 20%를 성공**으로 본다
- 공개 후 7일이 지난 기록 중 30일에 가장 가까운 기록을 쓴다. 한 대본으로 여러 편을 만들었으면 평균한다.
- 긍정 댓글은 지금은 직접 세거나, 댓글을 붙여 넣으면 사전 기반 분류기(`lexicon-ko-v1`)가 센다. 사람이 라벨을 단 댓글이 쌓이면 분류 모델로 바꾼다.

### 학습과 검증
- 표본이 수백 편 단위로 작으므로 단순하고 해석 가능한 모델로 시작한다. 대본 벡터를 주성분 최대 16개로 줄이고 구조 특징을 붙여
  L2 로지스틱 회귀를 학습한다. 벌점 세기는 학습 데이터 안의 교차 검증(로그 손실)으로 고른다.
- 부트스트랩 50회: 예측의 평균이 확률, 10~90% 분위가 범위다. **범위가 넓으면(40%p 이상) 화면에 "참고만 하라"고 표시**한다. 학습한 작품과 많이 다른 대본이다.
- **시간 순서 검증**: 공개 순으로 앞 80%로 학습하고 뒤 20%를 맞힌다. 미래 데이터로 과거를 맞히지 않는다.
- 비교 기준은 **장르별 성공률**이다. 검증 AUC가 0.5보다 높고 장르 기준 이상일 때만 활성화한다(관리자가 강제할 수 있다).
- 지표: AUC, 장르 기준 AUC, 상위 20% 적중률, 리프트(모델이 고른 상위 20%의 성공률 ÷ 전체 성공률), 브라이어 점수.

### 데이터가 쌓이기 전
| 정답 있는 대본 | 화면 |
|---|---|
| 3편 미만 | "모델 학습 전 · 학습 데이터 n/100편" |
| 3편 이상 | 위 + **벡터가 비슷한 작품**과 그 성과 (추천은 유사도 가중 성공률 순) |
| 100편 이상 + 학습·활성화 | **상위 20% 성과일 확률**과 범위, 가장 비슷한 작품 3편 |

기준 100편은 `ML_MIN_TRAINING_PAIRS`로 바꾼다.

## 원칙

- **작가에게는 판단 결과를 보여 주지 않는다.** 점수에 맞춰 쓰기 시작하면 대본이 뻔해지고 모델도 의미를 잃는다. 영상 제작자와 관리자만 본다.
- **학습 동의**(`trainingConsent`)는 대본마다 선택, 기본은 동의 안 함, 언제든 끌 수 있다. 학습 데이터에는 동의한 대본만 들어간다.
  대본은 플랫폼 안에서 벡터로만 바뀌고, 원문은 밖으로 내보내지 않는다.
- 공개한 대본은 동의와 상관없이 벡터화해 제작자에게 판단·추천을 보여 준다(마켓의 기본 기능). 이 점을 동의 화면에 적어 두었다.
- 비슷한 작품으로 보여 주는 대본이 지금 공개 상태가 아니면 제목을 가리고 작품 제목만 보인다.
- 정지·탈퇴한 작가의 대본은 학습 데이터에서 빠진다.

## 실행

`docker compose -f ops/compose.yaml up --build`에 `ml` 서비스가 함께 뜬다(포트를 열지 않고 API·워커만 부른다).
대본 내용이 바뀌면 워커가 요약 작업 때 벡터화도 요청한다. 실패해도 요약은 저장되고, 관리자 화면에서 "바뀐 대본 벡터화"로 다시 만든다.

화면에서 흐름을 확인하려면 합성 데모 데이터를 넣는다(개발 전용).

```bash
docker compose -f ops/compose.yaml exec api pnpm --filter api db:seed:ml-demo
```

학습 대본 200편(숨김, 학습 동의, 공개 작품·성과 포함)과 추천 후보 8편을 만든다. 긴장감 있는 장면이 많을수록 성과가 높게 나오도록 만든 **가짜 데이터**다.
관리자(`/admin/ml`)로 "바뀐 대본 벡터화" → "학습"을 누르면 모델이 활성화되고, 제작자 계정의 `/recommendations`와 대본 상세에서 결과를 볼 수 있다.
지우기: `... db:seed:ml-demo -- --remove`.

## API

| 경로 | 누가 | 내용 |
|---|---|---|
| `GET /scripts/:id/hit-insight` | 로그인한 다른 사람·관리자 (작가 본인 403) | `MODEL` / `NEIGHBORS` / `NOT_READY` |
| `GET /recommendations/scripts?limit=` | 로그인 | 공개 대본(자기 대본 제외)을 모델 순서로 |
| `POST /ml/comment-sentiment` | 로그인 | 댓글 긍정·부정 개수 (저장하지 않음) |
| `POST/GET /works/:id/performance` | 기획사·관리자 / + 출연자·보호자 | 성과 기록 (긍정 댓글, 채널 구독자 포함) |
| `GET /admin/ml/status`, `GET /admin/ml/models`, `POST /admin/ml/train`, `POST /admin/ml/embed-stale` | 관리자 | 상태, 학습 기록, 학습, 다시 벡터화 |
| `GET /admin/ml/training-set` | 관리자 | 학습 동의 대본의 메타데이터와 작품 성과 (원문 없음) |

ML 서비스 자체 API는 [services/ml/README.md](../services/ml/README.md).

## 다음에 할 것

1. **유튜브 분석 API 연동**: 채널 OAuth, 하루 한 번 성과 수집(`source = YOUTUBE_API`), 공개 후 7일·30일 시점을 정답으로 고정. 댓글도 같이 받아 긍정 댓글을 자동으로 센다.
2. **임베더 비교**: 해시 임베더 vs bge-m3 vs 우리 데이터로 미세조정한 임베더를 같은 시간 순서 검증으로 비교.
3. **장면 흐름 모델**: 저장해 둔 장면 벡터로 "첫 30초", 긴장 곡선 같은 순서 특징을 만든다(유튜브 단편은 초반 이탈이 결정적).
4. **블라인드 테스트**: 결과를 이미 아는 대본으로 "모델 고르기 vs PD 패널 vs 장르 평균"을 비교. 이 숫자가 영업·투자 자료가 된다.
5. **탐색 할당**: 추천의 10~20%는 모델이 확신하지 못하는 대본에 배정해 모델이 뻔한 대본만 고르지 않게 하고 맹점을 줄인다.
6. **데이터 확보**: 우리 플랫폼 작품(학습 동의), 크리에이터 제휴(대본+성과 제공), 공개 메타데이터만. 남의 대본을 허락 없이 학습하지 않는다.
