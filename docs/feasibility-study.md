# 흥행 판단 가능성 검증

데이터 확보 방식을 정하기 전에 먼저 확인할 질문이 있다.

> **대본만 보고, 같은 채널의 다른 영상보다 잘될 대본을 가려낼 수 있는가?**

이게 안 되면 "A급 PD의 감" 모델([hit-model.md](hit-model.md))은 성립하지 않는다. 되면 블라인드 테스트로 PD 패널과 비교하고,
그 결과를 보고 데이터 확보(제휴 확대, 플랫폼 학습 동의, 유튜브 연동)에 돈과 시간을 쓴다.

> 법률 검토 전 계획이다. 특히 "데이터를 어디서 얻나"와 [크리에이터 파일럿 약정 초안](policies/creator-pilot-agreement-draft.md)은 변호사 확인을 받은 뒤 모집을 시작한다.

## 데이터를 어디서 얻나

### 하지 않는 것
| 방법 | 하지 않는 이유 |
|---|---|
| 유튜브 크롤링, 남의 영상 자막·대본 수집 | 유튜브 개발자 정책이 스크래핑을 금지한다(III.E.6). "교육·연구용"이라고 정해도 상용 서비스를 만드는 팀의 사업성 조사라서 공정이용(저작권법 35조의5)에서 비영리 연구로 보기 어렵다. 그 데이터로 정한 기준·모델이 상용 모델로 넘어가면 문제도 같이 넘어간다. 그리고 자막은 완성된 영상의 대사라서, 촬영 전 대본을 판단하는 우리 질문에 맞지 않는다 |
| 일반 API 키로 여러 채널 공개 통계를 모아 분석 | 개발자 정책이 서로 다른 콘텐츠 소유자의 데이터를 합치는 것(III.E.2.a), API 데이터로 새 지표를 계산하는 것(III.E.4.h), 통계를 30일 넘게 보관하는 것(III.E.4.d)을 금지한다. 처음 제안했던 "공개 정보 조사" 단계는 이 때문에 뺐다 |
| 댓글 원문 보관 | 시청자 개인정보가 섞인다. 파일럿에서는 댓글 **개수**만 받는다 |
| 영상 파일, 출연자 얼굴·목소리 | 질문에 필요 없다. 개발 환경에 실제 배우 데이터를 넣지 않는다는 원칙과 같다 |

### 하는 것: 크리에이터 제휴 파일럿
대본형 단편 채널을 운영하는 크리에이터가 **자기 대본**과, **자기 유튜브 스튜디오에서 직접 내려받은 표 데이터**를 약정에 따라 준다.
권리자가 자기 자료를 직접 주는 것이고, 우리는 유튜브 API를 부르지 않는다.
- 대본을 쓴 사람이 채널 주인과 다르면 작가 동의도 받는다.
- 미성년 크리에이터는 법정대리인과 함께 약정한다(출연자 정책 7장과 같은 방식).

### 나중에 검토할 공식 통로
- **파생 지표 정책**(2026년 6월 1일 시행): 분석 용도로 신청해 승인받은 개발자는 채널 비교 지표·순위를 만들고 통계를 36개월까지 보관할 수 있다.
  모델 학습은 정책에 언급이 없으므로 신청 전에 확인한다. 플랫폼에서 유튜브 성과를 자동으로 모을 때(hit-model.md "다음에 할 것" 1번) 필요하다.
- **유튜브 연구자 프로그램**: 학위를 주는 대학의 학생·연구자·교수만 신청할 수 있고, 결과를 공개해야 하며, 연구를 상업적으로 팔 수 없다.
  산학 협력을 한다면 대학이 신청하고, 회사는 공개된 결론만 받는다.

## 단계

### 1. 파일럿 모집
| | |
|---|---|
| 대상 | 대본을 써서 찍는 단편 채널 (상황극, 숏드라마, 웹드라마 등) |
| 목표 | 채널 25~30곳 × 대본 40편 = **대본 약 1,000편**. 대본 300편·채널 8곳이 모이면 첫 분석을 돌린다 |
| 받는 것 | 대본 파일(.txt/.md), 스튜디오 고급 모드에서 동영상별 표 데이터(기간: 전체) CSV, 영상 ID ↔ 대본 파일 대응표 |
| 쓰는 영상 | 공개 후 30일이 지난 영상 |
| 주는 것 | 채널별 대본 리포트(이 채널에서 잘된 대본의 공통점), 전체 결과 요약. 보상은 별도로 정한다 |

### 1-1. 모집과 보상 (제안, 금액은 추정)
- **요구는 적게**: 계정 권한 없이 크리에이터가 직접 내려받은 파일만. 수익·시청자 정보·댓글 원문은 받지 않는다.
- **가치는 먼저**: 대본 10편만 먼저 받아 무료 채널 리포트를 돌려주고, 마음에 들면 나머지를 받는다.
- **약속은 문서로**: 변호사가 검토한 약정서, PD 비밀유지 서약, 사업자 정보와 담당자 실명 공개, 철회 시 7일 안에 삭제.
- **아는 사람부터**: 팀 인맥, 플랫폼 작가, 작가 커뮤니티 소개로 시작한다. MCN 소속 채널은 데이터 제공이 계약으로 막혀 있을 수 있으니 소속을 묻는다.
- **보상**: 채널당 정액 사례비(예: 20만 원) + 채널 리포트 + 창립 크리에이터 혜택(예: 첫해 수수료 감면)을 권한다. 30곳이면 약 600만 원.
  PD 패널은 5~8명 × 2회 × 회당 20~30만 원으로 약 200~480만 원. 금액은 시장 조사 전 추정치라 단가를 몇 곳에 물어본 뒤 정한다.
- **모집 예상(가정)**: 연락 150곳 → 답장 30% → 참여 20% ≈ 30곳. 첫 30곳 연락 결과로 고친다.

### 2. 분석
`python -m research analyze`가 아래 판정을 낸다. 대본에서 나온 정보만 쓴다(장면 벡터 + 구조 특징). 길이·게시 시각·썸네일은 넣지 않는다.

- **채널 빼고 맞히기**: 채널을 다섯 묶음으로 나눠, 한 묶음을 학습에서 빼고 맞힌다. 처음 보는 채널에도 통하는지 본다.
- **시간 순서**: 앞 80%로 학습하고 뒤 20%를 맞힌다.
- AUC는 **같은 채널 안의 (성공작, 아닌 작품) 쌍**만 센다. 신뢰구간은 채널 단위로 다시 뽑고, 순열 검정은 채널 안에서 정답을 섞는다(199회).
- 기준선: 구조 특징(장면 수, 대사 비율 등)만 쓴 모델. 벡터가 더하는 몫을 따로 본다.

### 3. 블라인드 테스트 (분석이 GO일 때만)
- 시간상 가장 최근 대본 중 40편(성공작 약 20%)을 문제로 뽑는다. 모델은 그보다 앞선 대본으로만 학습하고,
  **문제지를 만드는 순간 모델 점수를 정답지에 적어 둔다**(`python -m research blind-packet`).
- PD 5~8명이 문제지만 받아 대본마다 1~5점을 주고, 가장 잘됐을 것 8편을 고른다. 비밀유지 서약을 받은 PD에게만 보낸다.
- 채점(`blind-score`): 모델 vs PD 패널 평균 vs 구조 특징 기준선. 40편 한 번은 구간이 넓으므로 두 번(80편) 한다.
- "A급 PD의 감" 판정:
  - **목표**: 모델이 패널보다 크게 못하지 않다 (모델 − 패널 AUC 차이의 95% 구간 아래쪽 > −0.10), 그리고 모델이 고른 상위 20%의 적중률이 기본 성공률의 1.5배 이상
  - **강한 결과**: 차이 구간 아래쪽 > 0 (모델이 패널보다 낫다)

### 4. 다음 결정
| 결과 | 다음 |
|---|---|
| GO + 블라인드 목표 달성 | 데이터 확보 본격화: 제휴 확대, 플랫폼 학습 동의 강화, 파생 지표 정책 신청 검토 |
| MORE_DATA | 모집을 늘린다 (1,000편까지) |
| NO_GO | 대본만으로는 어렵다. 판단 시점을 바꾸거나(로그라인·기획안), 기능을 "비슷한 작품 찾기"로 줄인다 |

## 판정 기준 (데이터를 보기 전에 정하고 바꾸지 않는다)
| 판정 | 조건 |
|---|---|
| 분석 전 | 대본 300편 미만 또는 채널 8곳 미만 → MORE_DATA |
| **GO** | 채널 빼고 맞히기 AUC 95% 구간 아래쪽 > 0.5, 순열 검정 p ≤ 0.05, AUC ≥ 0.60, 리프트 ≥ 1.5, 시간 순서 AUC > 0.5 |
| (재확인) | 1,000편 전에 나온 GO는 "잠정 GO"다. 블라인드 테스트 준비는 시작하되, 1,000편에서 다시 GO가 나와야 확정한다 |
| **NO_GO** | 대본 1,000편 이상인데 AUC < 0.55이고 구간 위쪽 < 0.58 |
| MORE_DATA | 그 밖 |

- 0.60은 "같은 채널 안에서 성공작과 아닌 작품 한 쌍을 주면 열 번 중 여섯 번 맞힌다"는 뜻이다. 실무에 도움이 될 최소한으로 정했다.
- 부트스트랩 구간은 모델을 다시 학습할 때의 흔들림을 담지 못해 실제보다 좁다(합성 데이터에서 확인). 그래서 GO에는 순열 검정을 꼭 함께 보고, NO_GO는 점추정까지 낮을 때만 낸다.

## 정답 정의
같은 채널의 다른 영상과 비교한다. 채널마다 구독자와 알고리즘 노출이 크게 달라서다.
- 도달 = log(1+조회수) − 그 채널 중앙값
- 유지 = 평균 조회율(%) − 그 채널 중앙값. 대본 힘에 가장 가까운 지표다
- 반응 = log((좋아요+댓글+1) / (조회수+1)) − 그 채널 중앙값
- 점수 = 세 지표 z값의 평균, **상위 20% = 성공**. 한 대본으로 영상을 여러 편 만들었으면 평균한다
- 대본이 8편 미만인 채널은 뺀다

알려진 한계:
- 스튜디오 내보내기는 누적 성과다. 오래된 영상이 조금 유리하다(30일 이상만 쓰고 채널 안에서 비교해 줄였지만 남는다).
- 썸네일, 제목, 게시 시각, 출연자 연기의 영향이 섞여 있다. 이 몫은 대본만으로 못 맞히므로 AUC의 천장이 1보다 한참 낮다.

## 대본이 얼마나 필요한가
참 AUC가 이 값일 때, 95% 구간 아래쪽이 0.5를 넘을 확률(`python -m research power`).
합성 데이터에서 잰 실제 흔들림(근사식의 1.5배)을 반영했다.

| 대본 수 | AUC 0.55 | AUC 0.60 | AUC 0.65 | AUC 0.70 | AUC 0.65일 때 구간 반폭 |
|---|---|---|---|---|---|
| 300 | 12% | 35% | 67% | 91% | ±0.12 |
| 500 | 17% | 53% | 87% | 99% | ±0.10 |
| 1,000 | 30% | 82% | 99% | 100% | ±0.07 |
| 2,000 | 53% | 98% | 100% | 100% | ±0.05 |

300편으로는 신호가 강할 때(0.70)만 잡힌다. 실무 기준(0.60)을 확인하려면 **1,000편**이 필요하다.

## 도구 확인 (합성 데이터)
`research/synthetic.py`로 만든 **가짜** 데이터로 도구가 맞게 도는지 확인했다. 실제 가능성에 대해서는 아무것도 말하지 않는다.
- 신호를 심은 데이터(대본 360편, 채널 12곳): AUC 0.815, 순열 p = 0.01 → GO
- 신호가 없는 데이터(대본 300편, 채널 10곳) 25개: GO가 1번 나왔다(4%). 순열 검정을 넘은 것은 20개 중 1개(5%, 설계한 유의수준 그대로).
  AUC는 0.40~0.62에 퍼졌다. 즉 **최소 표본(300편)에서는 우연히 0.6을 넘는 일이 드물지 않으므로**, 300편에서 GO가 나와도 1,000편에서 다시 확인한다.
- 처음에는 채널 묶음별 모델 점수를 한 줄로 세워 AUC를 셌는데, 신호가 없을 때 0.39(우연보다 낮음)가 나왔다.
  묶음마다 절편이 달라서 생긴 착시라, 같은 채널 안 쌍만 세도록 바꿨다.

## 실행
`services/ml`에서 실행한다. 파일럿 데이터는 `research/data/`에 둔다(저장소·도커 이미지에 들어가지 않는다).

```
research/data/<채널>/
  channel.json   {"channel": "ch-01", "exportedAt": "2026-10-10", "agreementId": "P-001", "genre": "드라마"}
  studio.csv     스튜디오 표 데이터 (영어·한국어 열 이름 모두 읽는다. 다르면 columns.json으로 지정)
  mapping.csv    video_id,script[,genre]
  scripts/       대본 파일
```

```bash
python -m research synthetic research/out/demo-data      # 가짜 데이터로 흐름 확인
python -m research check research/data                     # 빠진 파일, 너무 최근 영상, 빠진 채널 점검
python -m research analyze research/data                   # → research/out/report.md, report.json
python -m research blind-packet research/data              # → research/out/blind/packet/ (PD용), key.csv (진행자만)
python -m research blind-score research/out/blind/key.csv 답안1.csv 답안2.csv
```

## 데이터 보관
- `research/data/`는 암호화한 디스크에만 두고, 분석 담당자만 연다. 클라우드 공유 폴더에 올리지 않는다.
- 제품 DB와 섞지 않는다. 분석 코드는 `hitmodel`의 계산 함수만 빌려 쓴다.
- 크리에이터가 철회하면 7일 안에 그 채널 폴더를 지우고 분석을 다시 돌린다.
- 파일럿이 끝나면 지운다. 크리에이터가 학습 이용에 따로 동의한 자료만 남긴다.
