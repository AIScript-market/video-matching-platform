# 공개 베타 준비 점검 (2026-10-14)

> 질문(Varev): 데이터를 더 받기 어려우니, 지금 기능으로 웹사이트를 공개해 이용자를 모아 보면 어떨까.
> 결론: **좋다. 다만 "누구나 가입하는 공개"가 아니라 "초대제 비공개 베타"로, 일부 기능을 끄고 시작한다.**

## 왜 초대제 베타인가

- 매칭 플랫폼은 작가와 제작자가 **같이** 있어야 굴러간다. 초대제로 양쪽 수를 맞추는 편이 빈 마켓처럼 보이지 않는다.
- 작가는 아이디어 유출을 가장 두려워한다. 초기에 아는 사람 위주로 받으면 신뢰를 쌓을 시간을 번다.
- 아래 "끄는 기능" 덕분에 법적 부담(민감정보, 결제)이 크게 준다.
- 목표 규모: 작가 30~50명, 제작자 10~20명. 4~6주 운영하며 피드백 기능(단계 0)과 검토 기록을 쌓는다.

## 할 일

### 코드 (Varev 쪽 Claude가 할 수 있는 것)

1. **베타 모드 스위치** (`BETA_MODE=true`): 출연자·캐스팅·흥행 판단 화면과 API 끄기, 코인 결제 끄기, 초대 코드 가입, 만 14세 이상 확인.
2. **보안**: 로그인·가입·메시지 요청 속도 제한, `JWT_SECRET` 등 필수 환경 변수 없으면 시작 거부, 운영에서 시드 계정·`/dev` 경로 제외, 보안 헤더.
3. **비밀번호 재설정** 메일 (발송 서비스는 아래 "결정할 것").
4. **운영용 이미지와 배포 설정** (Docker 운영판, 마이그레이션 자동 적용, 업로드 파일 저장 위치).
5. **작가 피드백 단계 0**과 제작자 쪽 결격 사유 표시·채널 유사도 정렬.
6. **약관·개인정보 처리방침·국외 이전 고지 페이지 초안** (법률 검토 전에는 게시하지 않는다).
7. 베타 운영 지표: 가입, 대본 공개, 검토, 컨택, 피드백 본 뒤 수정 (기록 테이블은 `prisma/` 변경이라 영훈 님 승인).

| 항목 | 권장 | 이유 |
